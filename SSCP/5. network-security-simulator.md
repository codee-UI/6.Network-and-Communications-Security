## 1. Defense in Depth & Device Placement

Layered trust domains: physical perimeter, perimeter network (DMZ), LAN, hosts, applications, data. A firewall sits on every connection crossing a domain boundary.

**Full forms**

| Term | Meaning |
|---|---|
| DMZ | Demilitarized Zone |
| LAN | Local Area Network |
| ACL | Access Control List |

**Working principle**

1. 🔵 *Internet → Perimeter FW*: Public request reaches the outer perimeter; facilities/physical security already limits site access.
2. 🟢 *Perimeter FW → DMZ Web App*: Perimeter firewall permits only web ports to trusted web apps in the DMZ.
3. 🔵 *DMZ Web App → Inner FW*: Web app needs data, so the request must cross the inner firewall.
4. 🟢 *Inner FW → Host / App*: Only authorised internal users/apps pass; the host's own firewall adds another check.
5. 🟢 *Host / App → Data Servers*: Application queries servers: final layer uses access control and encryption.
6. 🔴 *Internet → Inner FW*: Attacker tries to skip the DMZ: dropped. No single point of failure.

**Pros**

- No single point of failure
- Contains breaches to one zone
- Maps controls to each threat surface

**Cons**

- More devices to manage
- Rules need constant revalidation
- Added latency and cost

**Applications**

- **Commercial:** Banks and e-commerce: DMZ web tier, app tier, database tier.
- **Defense:** Classified enclaves separated by cross-domain guards and multiple perimeters.
- **Other:** Hospitals, universities, utilities (IT/OT segmentation).

## 2. Firewalls: Stateless, Stateful, Shallow

Static packet filters judge each packet alone; stateful firewalls track sessions and open ports dynamically; shallow inspection reads only L2-4 headers.

**Full forms**

| Term | Meaning |
|---|---|
| FTP | File Transfer Protocol |
| TCP | Transmission Control Protocol |
| UDP | User Datagram Protocol |
| SYN | Synchronize |
| ACK | Acknowledgement |
| OSI | Open Systems Interconnection |
| MAC | Media Access Control |
| DPI | Deep Packet Inspection |

**Working principle**

1. 🔵 *Client → Firewall*: Static filter: each packet checked alone against fixed rules (e.g. block port 79 'finger'). No session memory.
2. 🟢 *Firewall → Server*: Stateful: outbound SYN from inside is allowed and a state-table entry is created.
3. 🟢 *Server → Firewall*: SYN/ACK matches the entry, so the three-way handshake (SYN, SYN/ACK, ACK) completes.
4. 🟢 *Server → Client*: FTP data connection back to client port 1067 is allowed as part of FTP; a static filter would block it.
5. 🔴 *Server → Firewall*: Unsolicited packet with no state entry is dropped; idle sessions time out.

**Pros**

- Static: fast, low overhead
- Stateful: handles dynamic ports safely
- Shallow: cheap, built into routers

**Cons**

- Static: cannot open ports temporarily
- Stateful: needs memory/state table
- Shallow: blind to payload

**Applications**

- **Commercial:** Routers and office/home gateways; enterprise edge firewalls.
- **Defense:** Border gateways and tactical network edges.
- **Other:** Cloud security groups, school and campus networks.

## 3. Proxies: Circuit, Application, Web

A proxy splits each session in two (user-proxy, proxy-service), a management-approved man-in-the-middle.

**Full forms**

| Term | Meaning |
|---|---|
| AUP | Acceptable Use Policy |
| URL | Uniform Resource Locator |

**Working principle**

1. 🟢 *User → Proxy*: Session 1: the user connects to the proxy and authenticates.
2. 🟢 *Proxy → Web Server*: Session 2: proxy opens a separate connection. Circuit-level just relays; application-level inspects.
3. 🔵 *Web Server → Proxy*: Response is inspected for attacks (e.g. buffer overflow), logged and cached.
4. 🟢 *Proxy → User*: Clean content delivered; popular pages served from cache.
5. 🔴 *User → Proxy*: Request to a blocked site is denied and logged (AUP enforcement, evidence).

**Pros**

- Deep inspection (application-level)
- Hides internal hosts
- Logging, caching, authentication

**Cons**

- Circuit-level does not inspect content
- Application-level adds overhead
- One proxy per protocol

**Applications**

- **Commercial:** Corporate web gateways (Zscaler, Squid, Blue Coat).
- **Defense:** Controlled internet access and audit logs on classified networks.
- **Other:** Schools (content filtering), ISPs (caching).

## 4. Host-Based vs Network-Based Firewalls, Personal & NGFW

Network firewalls protect whole segments; host firewalls protect one endpoint and block outbound escape. Home networks need both.

**Full forms**

| Term | Meaning |
|---|---|
| SOHO | Small Office/Home Office |
| NGFW | Next-Generation Firewall |
| COTS | Commercial Off-The-Shelf |
| ISP | Internet Service Provider |
| IoT | Internet of Things |
| GUI | Graphical User Interface |

**Working principle**

1. 🟢 *Internet → Network FW*: Network firewall inspects all inbound traffic for every device behind it.
2. 🔵 *Network FW → LAN Switch*: Allowed traffic enters the LAN; alarms go via an out-of-band channel.
3. 🟢 *LAN Switch → Host FW*: Host firewall filters per-process traffic at the endpoint's interface.
4. 🟢 *Host FW → Processes*: Only permitted processes receive data; hostile software cannot phone home.
5. 🔴 *Internet → Network FW*: Login attempt to router with default username/password: the top self-inflicted weakness.

**Pros**

- Network: one choke point, easy to change
- Host: protects off-network laptops
- NGFW: adds ML threat detection

**Cons**

- Network: IoT inside LAN still exposed
- Host: many instances to manage
- Default credentials leave SOHO open

**Applications**

- **Commercial:** Windows Defender Firewall, Palo Alto/Fortinet NGFW.
- **Defense:** Hardened hosts plus enterprise NGFW.
- **Other:** Family routers, smart-home hubs, small clinics.

## 5. Wi-Fi Security: WEP → WPA3

Each protocol fell to attackers until WPA3 (2018) added SAE and forward secrecy.

**Full forms**

| Term | Meaning |
|---|---|
| WEP | Wired Equivalent Privacy |
| WPA | Wi-Fi Protected Access |
| TKIP | Temporal Key Integrity Protocol |
| MIC | Message Integrity Check |
| AES | Advanced Encryption Standard |
| CCMP | Counter Mode CBC-MAC Protocol |
| SAE | Simultaneous Authentication of Equals |
| KRACK | Key Reinstallation Attack |
| AP | Access Point |
| RC4 | Rivest Cipher 4 |
| GCMP | Galois/Counter Mode Protocol |
| ECDH | Elliptic Curve Diffie-Hellman |
| ECDSA | Elliptic Curve Digital Signature Algorithm |
| HMAC | Hashed Message Authentication Code |
| SHA | Secure Hash Algorithm |
| BIP-GMAC | Broadcast/Multicast Integrity Protocol Galois MAC |

**Working principle**

1. 🔴 *Attacker → Access Point*: WEP (RC4): statistical and known-plaintext attacks decrypt or inject traffic.
2. 🔵 *Client → Access Point*: WPA (2003) TKIP+MIC stopgap; WPA2 (2004) AES-CCMP with 802.1X; later broken.
3. 🟢 *Client → Access Point*: WPA3 (2018): SAE handshake resists offline guessing, no pre-shared key exposure.
4. 🟢 *Access Point → Client*: Forward secrecy: fresh session keys, so captured old traffic stays undecryptable.
5. 🔴 *Attacker → Access Point*: Dragonblood (2019) downgrade to WPA2/KRACK: fixed by software updates.

**Pros**

- WPA3: forward secrecy, no downgrade
- Enterprise: GCMP-256, HMAC-SHA384, ECDH/ECDSA-384
- Easier-to-remember passwords

**Cons**

- Legacy gear must be upgraded
- Public hotspots may not upgrade
- Early SAE flaws (Dragonblood)

**Applications**

- **Commercial:** Enterprise Wi-Fi (WPA3-Enterprise + RADIUS), retail, airports.
- **Defense:** Secure tactical and base wireless with 802.1X.
- **Other:** Homes, hospitals, campuses.

## 6. Network Access Control (802.1X)

Authenticate and posture-check users and devices before they get network access.

**Full forms**

| Term | Meaning |
|---|---|
| NAC | Network Access Control |
| IEEE | Institute of Electrical and Electronics Engineers |
| EAP | Extensible Authentication Protocol |
| EAPOL | EAP over LAN |
| RADIUS | Remote Authentication Dial-In User Service |

**Working principle**

1. 🔵 *Supplicant → Authenticator*: 1. EAPOL: the supplicant presents credentials/certificate to the switch or wireless controller.
2. 🔵 *Authenticator → Auth Server*: 2. Authenticator relays EAP via RADIUS/Diameter to the authentication server.
3. 🟢 *Auth Server → Authenticator*: Server checks identity and posture (antivirus, patches, approved software).
4. 🟢 *Authenticator → LAN/Internet*: 3. Compliant: port opens and the authorised services are granted.
5. 🔴 *Authenticator → Supplicant*: Non-compliant: denied, or quarantined until fixed.

**Pros**

- Only authorised devices connect
- Pre-access compliance screening
- Quarantine option

**Cons**

- Certificate lifecycle overhead
- Legacy/IoT devices lack a supplicant
- RADIUS server is critical

**Applications**

- **Commercial:** Corporate campuses, BYOD (Cisco ISE, Aruba ClearPass).
- **Defense:** Rogue-device blocking on military LANs.
- **Other:** Universities (eduroam), hospitals.

## 7. Intrusion Detection & Prevention

IDS senses events and raises alarms; IPS acts: block, reject, or divert.

**Full forms**

| Term | Meaning |
|---|---|
| IDS | Intrusion Detection System |
| IPS | Intrusion Prevention System |
| HIDS/HIPS | Host-based IDS/IPS |
| NIDS/NIPS | Network-based IDS/IPS |
| IoC | Indicator of Compromise |
| WAN | Wide Area Network |
| SOC | Security Operations Center |

**Working principle**

1. 🔵 *Internet → IDS Sensor*: Event: a packet with suspected malware arrives at the WAN port.
2. 🔵 *IDS Sensor → SOC Analyst*: Signal: scanner flags it; rules elevate it to an IoC and alarm the analyst.
3. 🟢 *IDS Sensor → IPS*: Detection triggers the prevention system.
4. 🟢 *IPS → Honeynet*: Suspicious traffic can be diverted to a honeynet for analysis.
5. 🔴 *IPS → Internet*: Packet rejected; source IP/MAC/port blocked.
6. 🟢 *IPS → Protected Net*: Clean traffic continues to the protected network.

**Pros**

- Real-time and post-facto detection
- Automated response
- HIDS and NIDS combined

**Cons**

- False positives can block good traffic
- Needs tuning and analysts
- Encrypted traffic limits visibility

**Applications**

- **Commercial:** Managed security services, cloud WAF/IPS.
- **Defense:** Cyber defence centres and mission networks.
- **Other:** Critical infrastructure (SCADA monitoring), healthcare.

## 8. Data Loss Prevention (DLP)

Keeps data inside the organisation-controlled environment (IRM/DRM instead controls access to protected material).

**Full forms**

| Term | Meaning |
|---|---|
| DLP | Data Loss Prevention |
| IRM | Information Rights Management |
| DRM | Digital Rights Management |

**Working principle**

1. 🔵 *Data Stores → DLP Engine*: 1-4. Define classes, label/tag data, continuously discover and map it.
2. 🔵 *DLP Engine → User*: 5. Real-time feedback warns users handling sensitive data.
3. 🔵 *User → DLP Engine*: User tries to email a 'Confidential' file externally.
4. 🔴 *DLP Engine → External*: 6. Policy enforced: transfer blocked.
5. 🔵 *DLP Engine → Data Stores*: 7. Report on DLP performance.

**Pros**

- Stops accidental and malicious leaks
- Supports compliance
- Educates users

**Cons**

- Classification effort
- False positives
- Hard with encrypted channels

**Applications**

- **Commercial:** Banks (card data), pharma IP protection.
- **Defense:** Controlled information and export-control enforcement.
- **Other:** Healthcare (patient records), legal firms.

## 9. Traffic Shaping, SD-WAN & Load Balancing

Make traffic meet a profile: restrict, queue, police; break out branch traffic locally; spread load.

**Full forms**

| Term | Meaning |
|---|---|
| WAN | Wide Area Network |
| SD-WAN | Software-Defined WAN |
| QoS | Quality of Service |

**Working principle**

1. 🔵 *Branch Office → SD-WAN Edge*: Branch traffic enters the SD-WAN edge.
2. 🟢 *SD-WAN Edge → Internet*: Internet-bound traffic breaks out locally, not backhauled to HQ.
3. 🔵 *SD-WAN Edge → Traffic Shaper*: Corporate traffic is classified by bandwidth/application.
4. 🟢 *Traffic Shaper → Load Balancer*: Video capped so conferencing stays reliable; excess queued or delayed.
5. 🟢 *Load Balancer → App Servers*: Requests spread across servers as load fluctuates.
6. 🔴 *Traffic Shaper → SD-WAN Edge*: Abusive flood policed: dropped.

**Pros**

- Saves bandwidth
- Supports IDS/IPS/DLP
- Scales with load

**Cons**

- Needs network-engineering coordination
- Misconfig throttles real work
- More moving parts

**Applications**

- **Commercial:** Retail chains and branch networks.
- **Defense:** Bandwidth-constrained field links.
- **Other:** Telcos, streaming, video-conferencing.

## 10. Unified Threat Management (UTM)

An all-in-one appliance, cluster or cloud service (SECaaS/SaaS) with one management portal.

**Full forms**

| Term | Meaning |
|---|---|
| UTM | Unified Threat Management |
| WAF | Web Application Firewall |
| VPN | Virtual Private Network |
| CTI | Cyberthreat Intelligence |
| SECaaS | Security as a Service |
| SaaS | Software as a Service |

**Working principle**

1. 🟢 *Internet → Firewall/WAF*: Traffic hits firewall/WAF and VPN termination.
2. 🟢 *Firewall/WAF → IPS*: IPS inspects against signatures and CTI feeds.
3. 🟢 *IPS → AV/Anti-malware*: Antivirus/antimalware scans payloads.
4. 🟢 *AV/Anti-malware → Web/Spam Filter*: Content filtering and antispam applied.
5. 🟢 *Web/Spam Filter → Users*: Clean traffic delivered; one portal manages everything.
6. 🔴 *AV/Anti-malware → Internet*: Malware found: dropped.

**Pros**

- Single pane of glass
- Lower cost/complexity
- Cloud option removes appliance work

**Cons**

- Single point of failure
- Performance limits with all features on
- Vendor lock-in

**Applications**

- **Commercial:** SMBs and branches (Fortinet, Sophos).
- **Defense:** Compact deployable kits for remote sites.
- **Other:** Schools, clinics, retail.

## 11. Remote Access & Zero Trust (Application Proxy)

Setup: DNS, security groups, IP/routing, certificates, network location server, access servers, then test. ZTA/SDP uses inside-initiated connections with no ingress firewall.

**Full forms**

| Term | Meaning |
|---|---|
| ZTA | Zero Trust Architecture |
| SDP | Software-Defined Perimeter |
| DNS | Domain Name System |
| MFA | Multifactor Authentication |

**Working principle**

1. 🟢 *Application → Cloud App Proxy*: Inside-initiated: the app connects OUT to the broker, so no inbound port is open.
2. 🔵 *Remote User → Cloud App Proxy*: User meets the application in the cloud and presents MFA/certificate.
3. 🔵 *Cloud App Proxy → Identity/Cert*: Identity, certificate validity and device posture checked.
4. 🟢 *Cloud App Proxy → Application*: Only that one app session is stitched, with no network-wide access.
5. 🔴 *Remote User → Application*: Direct scan or attack on the app: nothing reachable.

**Pros**

- No exposed ingress
- Least-privilege per app
- Works for remote users

**Cons**

- Depends on broker availability
- Needs identity/PKI processes
- Planning heavy

**Applications**

- **Commercial:** Zscaler, Cloudflare Access, Google BeyondCorp.
- **Defense:** Zero-trust initiatives (DoD).
- **Other:** Remote healthcare, government telework.

## 12. Switch & Router Security

Routers/switches are not security appliances but need hardening, plus ACLs.

**Full forms**

| Term | Meaning |
|---|---|
| CAM | Content Addressable Memory |
| VLAN | Virtual LAN |
| MFA | Multifactor Authentication |
| ACL | Access Control List |

**Working principle**

1. 🔴 *Rogue Device → Switch*: Rogue device plugs in: switch-port security shuts the port.
2. 🟢 *Admin → Router*: Remote admin access needs MFA.
3. 🟢 *Router → Switch*: Routing updates are authenticated for integrity.
4. 🔴 *Rogue Device → Switch*: CAM flooding / VLAN hopping attempt: blocked by CAM protection and VLAN controls.
5. 🟢 *Switch → Router*: Inter-device encryption prevents injection; ACLs filter.

**Pros**

- Stops rogue devices
- Protects routing integrity
- Cheap, built in

**Cons**

- Config errors are common
- Per-device effort
- Not a full firewall

**Applications**

- **Commercial:** Data-centre fabrics, ISPs.
- **Defense:** Hardened military routing.
- **Other:** Campuses, smart buildings.

## 13. Internet of Things (IoT)

NIST: devices with hardware, software, firmware and actuators that connect and exchange data. Perimeter is blurred.

**Full forms**

| Term | Meaning |
|---|---|
| IoT | Internet of Things |
| NIST | National Institute of Standards and Technology |
| RFID | Radio-Frequency Identification |
| TCP/IP | Transmission Control Protocol/Internet Protocol |

**Working principle**

1. 🔵 *IoT Sensor → Gateway/FW*: Sensors send data (embedded processor + comms software).
2. 🟢 *Gateway/FW → Cloud/App*: Gateway segments devices; policy limits what may connect.
3. 🟢 *Cloud/App → IoT Sensor*: Commands and updates flow back to actuators.
4. 🔴 *Botnet Attacker → IoT Sensor*: Weak default credentials: device joins a botnet (smart TVs/fridges seen in takedowns).
5. 🟢 *Gateway/FW → Botnet Attacker*: Segmentation and session management contain it.

**Pros**

- Huge automation and insight
- Anywhere/anytime connectivity
- Wide use cases

**Cons**

- Weak built-in security
- 25.4 bn devices by 2030 (Statista 2021 forecast)
- Unclear liability

**Applications**

- **Commercial:** Smart homes, logistics, building management.
- **Defense:** Battlefield sensors, asset tracking.
- **Other:** Farming, healthcare monitors, transport, toys.

## 14. Firewall Rule Design & Operations

Rules must fit organisational needs, consider traffic direction and TCP state, and be revalidated, backed up and archived.

**Full forms**

| Term | Meaning |
|---|---|
| HTTP | Hypertext Transfer Protocol |
| SYN | Synchronize |
| ACK | Acknowledgement |
| TCP | Transmission Control Protocol |

**Working principle**

1. 🔵 *Admin → Rule Set*: Start from organisational needs and access requirements.
2. 🔴 *Rule Set → Firewall*: Weak rule 'permit any, any, port 80': outsiders can reach rogue or internal-only web servers.
3. 🟢 *Rule Set → Firewall*: Better: 'permit <internal IP range> any eq 80' limits the source to your organisation.
4. 🟢 *Rule Set → Firewall*: Best: also match TCP state (SYN, SYN/ACK, ACK) with a session timeout that tears down idle dynamic rules.
5. 🔵 *Admin → Backup/Archive*: Back up and archive rules so they can be restored quickly after a disaster.
6. 🔴 *Attacker → Firewall*: Attackers probe for holes in rules, so revalidate whenever an application, service or source changes.

**Pros**

- Least-privilege traffic control
- Recoverable configuration
- Adapts to change

**Cons**

- Ongoing effort
- Mistakes open holes
- Needs monitoring

**Applications**

- **Commercial:** Change-managed enterprise firewalls.
- **Defense:** Auditable rule sets on classified networks.
- **Other:** Schools, hospitals, public sector.

## 15. Shallow vs Deep Packet Inspection

Shallow inspection checks L2-4 headers only; DPI also reads the payload.

**Full forms**

| Term | Meaning |
|---|---|
| OSI | Open Systems Interconnection |
| DPI | Deep Packet Inspection |
| IP | Internet Protocol |
| MAC | Media Access Control |

**Working principle**

1. 🔵 *Packet → Shallow (L2-4)*: Shallow inspection matches protocol (IP/UDP), IP addresses, ports and MAC addresses in headers.
2. 🔵 *Shallow (L2-4) → DPI Engine*: Header looks legitimate, so it is passed on for payload analysis.
3. 🟢 *DPI Engine → Network*: DPI finds clean content: forwarded.
4. 🔴 *DPI Engine → Packet*: DPI finds malware or protocol abuse in the payload: dropped.

**Pros**

- Shallow: cheap, found in router packet filters
- DPI: sees content

**Cons**

- Shallow: blind to payload
- DPI: costly and slower

**Applications**

- **Commercial:** Router ACLs; DPI in NGFW/IPS.
- **Defense:** Content-aware guards at network edges.
- **Other:** ISPs, campuses.

## 17. Wireless Threats & Defenses

Sniffing, default AP settings and rogue access; countered by IDS/IPS, NAC and unified endpoint tools.

**Full forms**

| Term | Meaning |
|---|---|
| AP | Access Point |
| IDS | Intrusion Detection System |
| IPS | Intrusion Prevention System |
| NAC | Network Access Control |
| UEM | Unified Endpoint Management |
| EDR | Endpoint Detection and Response |
| MTD | Mobile Threat Defense |
| SOHO | Small Office/Home Office |

**Working principle**

1. 🔴 *Wireless Sniffer → Default-config AP*: Sniffer captures all traffic on the wireless network, which can lead to information disclosure.
2. 🔴 *Wireless Sniffer → Default-config AP*: AP still has default admin credentials and no security: eavesdropping and modification.
3. 🟢 *Default-config AP → Wireless IDS/IPS*: Wireless IDS/IPS logs and blocks suspicious traffic.
4. 🟢 *Default-config AP → NAC 802.1X*: NAC blocks network access unless the user is properly authenticated.
5. 🔵 *Wireless IDS/IPS → UEM / EDR / MTD*: All network and device information is unified in UEM/EDR, with MTD for mobiles.

**Pros**

- Layered wireless protection
- SOHO can adopt enterprise concepts via training

**Cons**

- Tools aimed at large enterprises
- Public hotspots unenforceable

**Applications**

- **Commercial:** Enterprise Wi-Fi monitoring.
- **Defense:** Wireless intrusion monitoring on bases.
- **Other:** Cafes, small offices.

## 18. WPA2/3 Personal vs Enterprise

WPA3 comes in two modes; both provide forward secrecy and easier password selection.

**Full forms**

| Term | Meaning |
|---|---|
| GCMP-256 | 256-bit Galois/Counter Mode Protocol |
| HMAC-SHA384 | Hashed MAC with SHA-384 |
| ECDH | Elliptic Curve Diffie-Hellman |
| ECDSA | Elliptic Curve Digital Signature Algorithm |
| BIP-GMAC-256 | Broadcast/Multicast Integrity Protocol Galois MAC |

**Working principle**

1. 🟢 *Personal User → Access Point*: Personal: password-based SAE handshake; natural, memorable passwords allowed.
2. 🔵 *Enterprise User → Access Point*: Enterprise: 802.1X authentication.
3. 🟢 *Access Point → RADIUS Server*: Key establishment with ECDH and ECDSA (384-bit curve).
4. 🟢 *RADIUS Server → Access Point*: Key derivation HMAC-SHA384; authenticated encryption GCMP-256.
5. 🟢 *Access Point → Session Keys*: Robust management frame protection (BIP-GMAC-256); session keys changed routinely (forward secrecy).

**Pros**

- Strong crypto
- Forward secrecy

**Cons**

- Needs RADIUS infrastructure for Enterprise
- Hardware/software updates

**Applications**

- **Commercial:** Corporate and retail Wi-Fi.
- **Defense:** High-assurance 192-bit modes.
- **Other:** Homes, schools.

## 19. Remote Access Configuration & Operation

Plan, configure, test and keep remote access operational.

**Full forms**

| Term | Meaning |
|---|---|
| DNS | Domain Name System |
| IP | Internet Protocol |
| PKI | Public Key Infrastructure |

**Working principle**

1. 🔵 *Plan → DNS & Groups*: Plan architecture, management activities and servers; set up DNS and domain security groups.
2. 🔵 *DNS & Groups → Network/IP*: Configure network adapters, IP addresses, routing and management parameters.
3. 🔵 *Network/IP → Certificates*: Set up managing, storing, expiring and troubleshooting of digital certificates.
4. 🔵 *Certificates → Location Server*: Configure the network location server.
5. 🟢 *Location Server → Verify*: Configure, test and start remote access servers.
6. 🟢 *Verify → Plan*: Verify deployment, assets, services and people are ready to keep it running.

**Pros**

- Repeatable rollout
- Clear operations ownership

**Cons**

- Many dependencies
- Certificate lifecycle burden

**Applications**

- **Commercial:** VPN/ZTNA rollouts.
- **Defense:** Secure remote enclaves.
- **Other:** Remote healthcare, telework.

## 20. IoT: Origins, Use Cases & Vulnerabilities

NIST: devices that connect, interact and exchange data. Starting with RFID in 1999, networks no longer need conventional workstations.

**Full forms**

| Term | Meaning |
|---|---|
| RFID | Radio-Frequency Identification |
| NIST | National Institute of Standards and Technology |
| TCP/IP | Transmission Control Protocol/Internet Protocol |

**Working principle**

1. 🔵 *RFID Tag (1999) → Smart Devices*: Kevin Ashton's 1999 RFID presentation: networks without wired workstations.
2. 🟢 *Smart Devices → Use Cases*: Farming, healthcare, appliances, toys, logistics, transport, entertainment, smart homes, building management.
3. 🔵 *Smart Devices → Fuzzy Perimeter*: The perimeter is no longer just your building or network.
4. 🔴 *Botnet → Smart Devices*: 25% of infected devices in one botnet takedown were smart TVs and refrigerators.
5. 🟢 *Fuzzy Perimeter → Smart Devices*: Mitigation: strict policy on what connects, session management and risk-based security.

**Pros**

- Convenience and data
- Wireless connectivity

**Cons**

- Low security
- Unclear liability

**Applications**

- **Commercial:** Smart building management.
- **Defense:** Asset tracking.
- **Other:** Farming, healthcare.
