## 1. OSI model: encapsulation down, de-encapsulation up

### Animation steps
1. Data goes down from Layer 7 to Layer 1: Data -> Segment -> Packet -> Frame -> Bits.
2. The receiver reverses it, stripping each header.

### Working principle
1. The user data enters at Layer 7 through a program such as a browser.
2. Layers 6 and 5 format, encrypt and set up the session.
3. Layer 4 adds a TCP/UDP header (ports): a segment.
4. Layer 3 adds an IP header (logical addresses): a packet.
5. Layer 2 adds a MAC header and trailer: a frame.
6. Layer 1 turns the frame into bits on the medium. The receiver reverses every step.
7. NIST defines a packet as the logical unit of network communications produced by the transport layer, and transmission as information being electronically sent from one place to others.

### Full forms
| Term | Meaning |
|---|---|
| OSI | Open Systems Interconnection |
| PDU | Protocol Data Unit |
| TCP/IP | Transmission Control Protocol / Internet Protocol |
| MAC | Media Access Control |
| LAN | Local Area Network |
| WAN | Wide Area Network |

### Pros
- Modular: each layer can change independently
- Vendors interoperate
- Easier troubleshooting and teaching

### Cons
- Headers add overhead
- TCP/IP merges layers 5-7, so real stacks are less strict
- Cross-layer protocols (TLS) do not fit neatly

### Where it is used
Commercial: every enterprise LAN, ISP and cloud data centre. Defence: tactical networks mixing radio, satellite and fibre under one IP layer. Other: hospitals, railways, industrial control.

### Threats and countermeasures
- **Threats:** Attacks can begin at any layer.
- **Defences:** Defence in depth: controls at every layer, zero trust, monitoring.

## 2. Layer 1: Physical, bits on the medium

### Animation steps
1. **Frame to bits** (Host A internal): Layer 2 hands a frame down. Layer 1 converts it to a stream of ones and zeros suited to the medium (copper, fibre, radio).
2. **Weak signal 1010** (Host A -> Repeater): The signal weakens (attenuation) and picks up noise as it travels.
3. **Regenerate bits** (Repeater internal): A repeater regenerates the received bits cleanly. An amplifier only boosts energy and may boost errors too.
4. **Clean signal 1010** (Repeater -> Host B): The regenerated signal travels further down the medium.
5. **Bits to frame** (Host B internal): Bits are reassembled into bytes, put into a frame, the header is stripped and the frame goes up to Layer 2.

### Working principle
1. Ethernet uses bus (logical) over star or point-to-point (physical) topologies.
2. Before sending, a device listens (carrier sense). If two send at once, a collision is detected and both retry (CSMA/CD).
3. Full-duplex Ethernet has no collisions.
4. Media: coaxial, twisted pair, fibre, radio. Speeds from 10 Mbps up to 1 Gbps (1000BASE-T/SX/LX).
5. InfiniBand adds flow control and virtual lanes for predictable performance (up to 800 Gb/s).

### Full forms
| Term | Meaning |
|---|---|
| CSMA/CD | Carrier Sense Multiple Access / Collision Detection |
| UTP | Unshielded Twisted Pair |
| Mbps | Megabits per second |
| 100BASE-TX | 100 Mbps over twisted pair |
| 100BASE-FX | 100 Mbps over multimode fibre |
| 1000BASE-T | 1 Gbps over twisted pair |
| RF | Radio Frequency |
| IEEE 802.3 | Ethernet standard |
| InfiniBand | High-speed switched fabric for supercomputers |

### Pros
- Simple, cheap, fast media
- Fibre is immune to electrical interference
- Full-duplex removes collisions

### Cons
- Repeaters and hubs are obsolete
- Attenuation and interference
- Wiring and radio can be tapped physically

### Where it is used
Commercial: Cat6 and fibre in offices, InfiniBand in AI/HPC data centres. Defence: shielded or fibre cabling, RF surveillance of Wi-Fi space. Other: factories, hospitals, supercomputing labs.

### Threats and countermeasures
- **Threats:** Cable taps, USB implants, rogue Wi-Fi with high-gain antennas, drones, signal injection, interference.
- **Defences:** Protect cable ways and cabinets, shielded or optical media, RF surveillance, monitoring from Layer 2 upward.

## 3. Layer 1/2 Ethernet: CSMA/CD, hubs, repeaters and amplifiers

### Animation steps
1. **Listen: line idle** (Host A internal): Carrier sense: A checks that nobody is transmitting.
2. **Listen: line idle** (Host B internal): B also finds the line idle at the same moment.
3. **A transmits** (Host A -> Shared bus): A starts sending.
4. **B transmits too** (Host B -> Shared bus): B starts before A’s signal reaches it.
5. **Collision detected** (Shared bus internal): Both signals overlap. Devices detect the collision and send a jam signal.
6. **Random back-off** (Host A internal): A waits a random time.
7. **Longer back-off** (Host B internal): B waits a different random time.
8. **A retransmits OK** (Host A -> Shared bus): The retry succeeds. Full-duplex Ethernet avoids all this.

### Working principle
1. Ethernet II and IEEE 802.3 differ only in header field details, with no security significance. Some platforms support both, others need options switched.
2. Physical topologies: bus, star, point-to-point. Logical topology: bus.
3. CSMA/CD: listen, send, detect collision, back off, retry. Too many collisions cut throughput.
4. Repeaters regenerate bits (digital ones give basic error detection). Amplifiers only boost energy and may inject errors. Hubs repeat to every port.
5. Repeaters and hubs are obsolete in modern LANs.

### Full forms
| Term | Meaning |
|---|---|
| CSMA/CD | Carrier Sense Multiple Access / Collision Detection |
| Hub | Layer 1 multiport repeater |
| Repeater | Regenerates received bits |
| Amplifier | Boosts signal energy (can boost errors) |
| Ethernet II | Older DIX frame format |
| IEEE 802.3 | Standard Ethernet frame format |
| Full-duplex | Send and receive at once |
| Wetware | Policies and training loaded into people |

### Pros
- Little overhead compared with token ring
- Efficient when traffic is light

### Cons
- Retransmissions under load
- Hubs share one collision domain

### Where it is used
Commercial: legacy LANs, now replaced by switched full-duplex. Defence: older equipment still met in audits. Other: labs and teaching networks.

### Threats and countermeasures
- **Threats:** Sniffer taps on cables and hubs, collision-based denial of service.
- **Defences:** Switches, full-duplex links, protected cabling.

## 4. Layer 2: Data Link, frames and MAC addresses

### Animation steps
1. **ARP: who has IP B?** (Host A -> Switch): A knows B’s IP but needs its MAC, so it broadcasts an ARP request.
2. **Flooded to all ports** (Switch -> Host B): The switch learns A’s MAC and floods the broadcast.
3. **ARP reply: my MAC** (Host B -> Switch): B replies directly (unicast) with its MAC.
4. **Reply forwarded** (Switch -> Host A): The switch learns B’s port and forwards the reply.
5. **Frame to MAC B** (Host A -> Switch): A builds a frame: destination MAC, source MAC, payload, check value (FCS).
6. **Forward to B only** (Switch -> Host B): The switch looks up its MAC table and sends the frame out of one port.

### Working principle
1. Frames carry source and destination MAC addresses.
2. Switches learn which MAC is on which port.
3. Unknown or broadcast frames are flooded.
4. FCS detects corrupted frames.

### Full forms
| Term | Meaning |
|---|---|
| MAC | Media Access Control |
| ARP | Address Resolution Protocol |
| FCS | Frame Check Sequence |
| VLAN | Virtual LAN |
| STP | Spanning Tree Protocol |
| 802.1X | Port-based access control |

### Pros
- Fast local delivery
- VLANs segment traffic
- Switches isolate collision domains

### Cons
- Broadcast storms and loops without STP
- MAC spoofing and ARP poisoning

### Where it is used
Commercial: office and campus switching. Defence: 802.1X port security, MAC filtering. Other: data-centre fabrics.

### Threats and countermeasures
- **Threats:** ARP poisoning, MAC flooding, VLAN hopping.
- **Defences:** Port security, 802.1X, dynamic ARP inspection, VLAN hygiene.

## 5. Layer 3: Network, IP addressing and routing

### Animation steps
1. **ICMP Echo (ping)** (Host A -> Router): Host A sends an IP packet to B’s address, TTL 64. The destination is on another network, so it goes to the router.
2. **Route lookup, TTL-1** (Router internal): The router reads the IP destination, consults its routing table and picks the next hop. TTL drops by one.
3. **Forward packet** (Router -> Host B): The packet is forwarded. Segments too long are split into packets.
4. **Echo reply** (Host B -> Router): B answers with an ICMP Echo Reply.
5. **Reply forwarded** (Router -> Host A): A displays the round-trip time. Traceroute uses rising TTL values the same way.

### Working principle
1. Layer 3 manages logical addressing and forwards packets to the right network.
2. Routers read the IP destination and choose the next hop from the routing table.
3. Unknown destinations go to the default gateway.
4. ICMP (ping, traceroute) and IGMP (multicast groups) are routed protocols.
5. Boundary routers use ACLs for basic filtering.
6. Layer 3 is where the move from IPv4 to IPv6 appears.
7. Attackers fingerprint the network here; fingerprints can be sold.

### Full forms
| Term | Meaning |
|---|---|
| IP | Internet Protocol |
| IPv4/IPv6 | IP versions 4 and 6 |
| ICMP | Internet Control Message Protocol |
| IGMP | Internet Group Management Protocol |
| TTL | Time To Live |
| ACL | Access Control List |
| DMZ | Demilitarized Zone |
| VLAN | Virtual LAN |
| NGFW | Next-Generation Firewall |

### Pros
- Connects disparate networks
- Scales globally
- IPv6 gives a huge address space

### Cons
- Misconfigured or unpatched routers
- Reveals network fingerprint
- Routing lookups cost CPU time

### Where it is used
Commercial: ISPs, branch-to-HQ WANs. Defence: segmented secure enclaves and gateways. Other: smart grids, airline reservation networks.

### Threats and countermeasures
- **Threats:** RIP attacks, routing table poisoning, ICMP attacks, ping flood, Smurf, IP spoofing, sniffing.
- **Defences:** Secure ICMP, authenticated route exchange, ACLs, NGFW inspection, VLANs, microsegmentation, zero trust.

## 6. Layer 3: ICMP ping and traceroute with TTL

### Animation steps
1. **Probe TTL=1** (Host -> Router 1): Traceroute sends a packet with TTL 1.
2. **Time Exceeded** (Router 1 -> Host): Router 1 drops it and returns an ICMP message, revealing itself.
3. **Probe TTL=2** (Host -> Router 2): The next probe has TTL 2 and passes Router 1.
4. **Time Exceeded** (Router 2 -> Host): Router 2 reveals itself. The path is mapped hop by hop.

### Working principle
1. ICMP exchanges control messages between hosts and gateways.
2. Ping and traceroute are built on ICMP.
3. Administrators and users diagnose failures with it.
4. Attackers can misuse it for MITM and DoS.

### Full forms
| Term | Meaning |
|---|---|
| ICMP | Internet Control Message Protocol |
| TTL | Time To Live |
| MITM | Man-in-the-Middle |
| DoS | Denial of Service |

### Pros
- Essential diagnostics
- Simple

### Cons
- Reveals topology
- Can be abused

### Where it is used
Commercial: NOC troubleshooting. Defence: controlled ICMP filtering. Other: any IP network.

### Threats and countermeasures
- **Threats:** ICMP attacks, ping flood.
- **Defences:** Secure ICMP, rate limits.

## 7. Layer 3: IGMP and multicast group management

### Animation steps
1. **IGMP join** (Host -> Multicast agent): The host asks the local multicast agent to join a group.
2. **Relay group interest** (Multicast agent -> Neighbour agent): Agents relay multicasts to neighbouring agents.
3. **Multicast stream** (Neighbour agent -> Multicast agent): The stream arrives with no reliable session.
4. **Stream to members** (Multicast agent -> Host): Only members receive it. Delivery is not guaranteed.
5. **IGMP leave** (Host -> Multicast agent): The host leaves the group.

### Working principle
1. Each network and subnetwork needs at least one multicast agent.
2. Hosts send IGMP messages to join and leave groups.
3. Agents route and relay multicasts.
4. No reliable sessions, to cut overhead.

### Full forms
| Term | Meaning |
|---|---|
| IGMP | Internet Group Management Protocol |
| IPTV | Internet Protocol Television |

### Pros
- Saves bandwidth
- Scales to many viewers

### Cons
- No delivery guarantee
- Eavesdropping and abuse

### Where it is used
Commercial: IPTV, financial feeds. Defence: group messaging. Other: lecture streaming.

### Threats and countermeasures
- **Threats:** Unauthorised joins, DoS.
- **Defences:** IGMP snooping, access control.

## 8. Layer 3 attack: ping flood, IP spoofing and Smurf

### Animation steps
1. **Echo to broadcast** (Attacker -> Broadcast network): The attacker sends ICMP echo to the broadcast address with the victim’s forged source address.
2. **All hosts receive** (Broadcast network internal): Every host on the network gets it.
3. **Mass echo replies** (Broadcast network -> Victim): Every host replies to the victim.
4. **Victim overwhelmed** (Victim internal): Denial of service. The attacker was never visible.

### Working principle
1. Attackers gather network fingerprints at Layer 3.
2. Spoofing hides the origin and redirects replies.
3. Related: RIP attacks, routing table poisoning, packet sniffing.

### Full forms
| Term | Meaning |
|---|---|
| Smurf | ICMP broadcast flood with spoofed source |
| IP spoofing | Forged source address |
| Fingerprint | Technical profile of a target |
| DoS | Denial of Service |

### Pros
- (Attack, so none)

### Cons
- Outage
- Foothold for command and control

### Where it is used
Seen in: denial-of-service campaigns against commercial and public sites.

### Threats and countermeasures
- **Threats:** Smurf, ping flood, spoofing.
- **Defences:** Disable directed broadcasts, secure ICMP, packet filtering, NGFW, ACLs, microsegmentation, zero trust.

## 9. Layer 3 transmission methods: unicast, broadcast, multicast, anycast, geocast

### Animation steps
1. Unicast: one-to-one. Private, but no redundancy and open to DDoS.
2. Broadcast: one-to-everyone on the segment. Used by ARP and discovery, but noisy and abusable for DoS.
3. Multicast: only hosts that joined the group (via IGMP) receive it. More efficient than broadcast.
4. Anycast: one-to-one-of-many. Group {B, D} share an address and the nearest or least busy node answers. Used by CDNs and DNS, costly to deploy.
5. Geocast: like broadcast but limited to a geographic area (here A and B). Efficient for regional delivery.

### Working principle
1. Unicast: sender to one host.
2. Broadcast: sender to all hosts on the segment (ARP request).
3. Multicast: sender to a joined group.
4. Anycast: sender to the closest member of a group.
5. Geocast: sender to hosts in a defined region.
6. The simulator highlights which hosts receive each mode.

### Full forms
| Term | Meaning |
|---|---|
| DDoS | Distributed Denial of Service |
| DoS | Denial of Service |
| ARP | Address Resolution Protocol |
| CDN | Content Delivery Network |
| IGMP | Internet Group Management Protocol |
| MAC | Media Access Control |

### Pros
- Unicast: private
- Multicast: bandwidth efficient
- Anycast: fast, resilient service
- Geocast: reduces unnecessary traffic

### Cons
- Unicast: no redundancy
- Broadcast: noisy, DoS risk
- Multicast: eavesdropping, abuse
- Anycast: extra servers and routing cost

### Where it is used
Commercial: CDNs and public DNS (anycast), IPTV and stock-ticker feeds (multicast). Defence: regional alerts and tactical group messaging (geocast, multicast). Other: emergency alert systems, software updates.

### Threats and countermeasures
- **Threats:** Broadcast floods, multicast abuse.
- **Defences:** Broadcast limits, VLANs, IGMP snooping, rate limiting.

## 10. Routers and routing protocols: RIP, OSPF, BGP, MPLS

### Animation steps
1. RIP (distance vector): picks the fewest hops (2), even though both links are slow.
2. OSPF (link-state): all routers share link states and run shortest-path-first. It picks the 3-hop path because the fast links give the lowest cost.
3. BGP (path vector): between autonomous systems, routers advertise prefixes with their AS path. Misconfiguration can redirect traffic.
4. MPLS: R1 pushes a label, R3 and R4 forward by label with no IP lookup, R5 pops it and routes normally.

### Working principle
1. Static routes work for tiny networks. Larger ones use dynamic protocols.
2. Interior protocols (RIP, EIGRP, OSPF, IS-IS) run inside an AS. Exterior (BGP) runs between ASes.
3. Distance vector (RIP) counts hops. Link-state (OSPF, IS-IS) floods LSAs and each router runs shortest-path-first.
4. Path vector (BGP) keeps loop-free AS paths.
5. MPLS (32-bit header: 20-bit label, 3-bit class of service, 1-bit stack, 8-bit TTL) labels paths once, then forwards by label.

### Full forms
| Term | Meaning |
|---|---|
| RIP | Routing Information Protocol |
| OSPF | Open Shortest Path First |
| IS-IS | Intermediate System to Intermediate System |
| BGP | Border Gateway Protocol |
| MPLS | Multiprotocol Label Switching |
| AS/ASN | Autonomous System (Number) |
| LSA | Link-State Advertisement |
| ABR | Area Border Router |
| ASBR | AS Boundary Router |
| LSR | Label Switching Router |
| FEC | Forwarding Equivalence Class |
| SD-WAN | Software-Defined WAN |
| IGRP/EIGRP | (Enhanced) Interior Gateway Routing Protocol |
| RFC | Request for Comment |
| TTL | Time To Live |
| QoS | Quality of Service |
| IETF | Internet Engineering Task Force |

### Pros
- Dynamic routing adapts to failures
- OSPF converges quickly and avoids loops
- MPLS gives traffic engineering, multiservice support, fast reroute

### Cons
- RIP ignores speed (max-hop limit)
- Link-state needs CPU and memory
- BGP depends on correct configuration
- MPLS can cost more than SD-WAN

### Where it is used
Commercial: BGP runs the internet backbone, OSPF in enterprises, MPLS in carrier VPNs, SD-WAN as an alternative. Defence: segregated routing domains and controlled BGP peering. Other: universities, stock exchanges, utilities.

### Threats and countermeasures
- **Threats:** Routing table poisoning, BGP misconfiguration or hijack, RIP attacks.
- **Defences:** Authenticated route exchange, route filtering, proper configuration, monitoring.

## 11. Routing basics: static routes, default gateway, ACL and DMZ

### Animation steps
1. **Packet to remote network** (Host -> Boundary router): The router reads the IP destination.
2. **ACL check** (Boundary router internal): The ACL permits or denies by source, destination, port or service.
3. **No route: default gateway** (Boundary router internal): An unknown destination goes to the default gateway.
4. **Forward to upstream** (Boundary router -> Internet): Hope that router knows more.

### Working principle
1. ARPANET needed only static routes. Growth required dynamic routing, standardised by RFCs.
2. Boundary routers sit at the DMZ between LAN and the outside world.
3. Protocols are classed by purpose (interior or exterior), behaviour (classful or classless) and operation (distance vector, path vector, link-state).
4. Hierarchy: Interior = distance vector (RIPv1, RIPv2, IGRP obsolete; RIPv3, EIGRP) and link-state (IS-IS, OSPF). Exterior = path vector (BGP).
5. Autonomous systems exchange routes with exterior protocols and use interior ones inside.

### Full forms
| Term | Meaning |
|---|---|
| ACL | Access Control List |
| DMZ | Demilitarized Zone |
| ARPANET | Original packet network (4 hosts) |
| Static route | Hand-defined path |
| Default gateway | Fallback router |
| Classful/classless | Fixed or flexible address boundaries |
| EGP/IGP | Exterior/Interior Gateway Protocol |

### Pros
- Simple first-line filtering
- Default routes keep tables small

### Cons
- ACLs are basic
- Misconfiguration is common

### Where it is used
Commercial: office-to-ISP edge. Defence: enclave perimeters. Other: campuses.

### Threats and countermeasures
- **Threats:** Misconfiguration, poisoning.
- **Defences:** Tight ACLs, patching.

## 12. OSPF: LSAs, areas, ABR and ASBR

### Animation steps
1. Area 1: each router floods link-state advertisements (LSAs) about its own links. All build the same map and run shortest-path-first.
2. The area border router (ABR) segments the AS into areas and summarises routes between them, keeping updates smaller.
3. The AS boundary router (ASBR) connects to another autonomous system and manages routing between them.
4. Convergence: after a failure LSAs flood quickly, avoiding loops and count-to-infinity. Cost: CPU and memory.

### Working principle
1. OSPF works at the Network layer. IS-IS works at the Data Link layer of OSI.
2. OSPFv1 (RFC 1131), v2 (RFC 1583, updated by RFC 2328) learn and advertise routes via LSAs.
3. Routers track the state of all their links, so it is link-state.
4. Smaller, more frequent updates and fast convergence; needs CPU and memory.

### Full forms
| Term | Meaning |
|---|---|
| OSPF | Open Shortest Path First |
| LSA | Link-State Advertisement |
| ABR | Area Border Router |
| ASBR | AS Boundary Router |
| IS-IS | Intermediate System to Intermediate System |
| SPF | Shortest Path First |

### Pros
- Fast convergence
- Loop-free, stable

### Cons
- CPU and memory heavy
- Design effort for areas

### Where it is used
Commercial: enterprise and campus cores, ISPs. Defence: large internal networks. Other: utilities, universities.

### Threats and countermeasures
- **Threats:** Forged LSAs, poisoning.
- **Defences:** Route authentication, filtering.

## 13. MPLS: label switching across the WAN

### Animation steps
1. The ingress edge node computes the best path once and pushes a 32-bit header: 20-bit label, 3-bit class of service, 1-bit stack, 8-bit TTL.
2. The label switching router (LSR) forwards on the label alone, with no per-packet routing lookup, and swaps the label.
3. The last LSR hands over; the egress edge removes the label and delivers by normal IP routing.
4. Label switch path: traffic engineering, multiservice, Fast Reroute for resilience. Many firms now choose SD-WAN for cost.

### Working principle
1. Runs across Layers 2 and 3. Standardised by IETF, RFC 3031.
2. Components: edge node, label switching router, label switch path (packets in one FEC).
3. Future packets reuse the label.
4. Advantages: traffic engineering, multiservice, resilience.

### Full forms
| Term | Meaning |
|---|---|
| MPLS | Multiprotocol Label Switching |
| LSR | Label Switching Router |
| LSP | Label Switch Path |
| FEC | Forwarding Equivalence Class |
| IETF | Internet Engineering Task Force |
| SD-WAN | Software-Defined WAN |
| QoS | Quality of Service |

### Pros
- Lower latency
- QoS control
- Fast Reroute

### Cons
- Cost versus SD-WAN
- Carrier dependent

### Where it is used
Commercial: carrier VPNs for banks and retailers. Defence: private WAN backbones. Other: telecom core networks.

### Threats and countermeasures
- **Threats:** Label spoofing, misconfiguration.
- **Defences:** Edge filtering, provider trust.

## 14. Layer 4: Transport, TCP handshake, UDP and ports

### Animation steps
1. **SYN** (Client -> Server): Setup: the client sends SYN (SYN-SENT).
2. **SYN-ACK** (Server -> Client): The server allocates resources and replies SYN-ACK (SYN-RECEIVED).
3. **ACK** (Client -> Server): The client acknowledges. Both are ESTABLISHED.
4. **DATA, then ACK** (Client -> Server): Use: payloads flow and are acknowledged, with retransmission if lost.
5. **FIN** (Client -> Server): Termination: the client has finished and sends FIN (FIN WAIT 1).
6. **ACK** (Server -> Client): The server acknowledges (CLOSE WAIT, client FIN WAIT 2).
7. **FIN** (Server -> Client): The server closes its side (LAST ACK).
8. **ACK** (Client -> Server): Final ACK. Both are CLOSED.

### Working principle
1. TCP: connection-oriented, reliable, three-way handshake, then data, then four-step close.
2. UDP: connectionless, just sends, no acknowledgment. Good for delay-sensitive traffic.
3. Ports: HTTP 80, HTTPS 443, SSH 22, Telnet 23, DNS 53 (TCP and UDP), SMTP 25/587, FTP 20/21, TFTP 69 (UDP), SNMP 161/162, BGP 179.
4. Ranges: well-known 0-1023, registered 1024-49151, dynamic 49152-65535.
5. Firewalls filter on ports and connection state.
6. UDP is connectionless, so routers and firewalls have no state to observe.
7. Malicious actors can malform TCP handshakes for DoS or reconnaissance.

### Full forms
| Term | Meaning |
|---|---|
| TCP | Transmission Control Protocol |
| UDP | User Datagram Protocol |
| SYN | Synchronize |
| ACK | Acknowledge |
| FIN | Finish |
| IANA | Internet Assigned Numbers Authority |
| HTTP(S) | Hypertext Transfer Protocol (Secure) |
| DNS | Domain Name Service |
| SMTP | Simple Mail Transfer Protocol |
| SSH | Secure Shell |
| FTP | File Transfer Protocol |
| TFTP | Trivial FTP |
| SNMP | Simple Network Management Protocol |
| BGP | Border Gateway Protocol |
| RADIUS | Remote Authentication Dial-In User Service |

### Pros
- TCP: reliable, ordered
- UDP: low overhead, fast
- Ports multiplex many services

### Cons
- TCP: handshake overhead and slow loss recovery
- UDP: no state, useful to attackers
- Port remapping only obscures services

### Where it is used
Commercial: web, e-commerce and banking (TCP), VoIP, video and DNS (UDP). Defence: stateful firewalls, secure file transfer, tactical voice (UDP). Other: telemedicine, online gaming, IoT telemetry.

### Threats and countermeasures
- **Threats:** SYN floods, port scanning, malformed handshakes, UDP-based attacks.
- **Defences:** Stateful firewalls, closing unused ports, use secure protocol versions, rate limiting.

## 15. Layer 4: UDP, dynamic ports and firewalls

### Animation steps
1. **UDP datagram to port 53** (Client -> Firewall): No handshake: the sender just sends.
2. **Rule check by port** (Firewall internal): Firewalls filter on port and protocol. UDP gives no state to watch.
3. **Forward** (Firewall -> Server): The datagram reaches the DNS service.
4. **Reply (no ACK)** (Server -> Client): No acknowledgment is expected. The service answers on a dynamic port for the session, then releases it.

### Working principle
1. Port remapping can obscure services but only if all parties agree.
2. Firewalls moved from hardware into operating systems and virtual agents.
3. Low overhead suits delay-sensitive traffic.

### Full forms

| DNS | Domain Name Service |
| ACK | Acknowledge |
| IETF | Internet Engineering Task Force |

### Pros
- Fast
- Low overhead

### Cons
- No state; useful for attacks
- No guarantee

### Where it is used
Commercial: DNS, VoIP. Defence: tactical voice. Other: IoT.

### Threats and countermeasures
- **Threats:** UDP floods.
- **Defences:** Firewall rules, rate limits.

## 16. Layer 5: Session, set up, maintain, tear down

### Animation steps
1. **Session request** (Client -> Auth server): A Point-to-Point Protocol (PPP) session asks to start.
2. **Challenge** (Auth server -> Client): The server sends a random challenge.
3. **hash(secret+challenge)** (Client internal): CHAP hashes the credential instead of sending the password.
4. **Response (hash)** (Client -> Auth server): The client returns the hash.
5. **Compare hashes** (Auth server internal): The server computes its own hash and compares.
6. **Success: session up** (Auth server -> Client): The session is established.
7. **Data (RPC calls)** (Client -> Auth server): Peers exchange data while the session is maintained.
8. **Terminate** (Client -> Auth server): The session is torn down.

### Working principle
1. Layer 5 gives a persistent logical connection between peers.
2. Authentication: PAP (weak), CHAP (hashed), EAP (stronger, EAP-TLS in Wi-Fi), PEAP (certificates).
3. Tunnelling: PPTP first, now replaced by VPNs.
4. RPC lets a client run a procedure on another host.
5. ISO 7498-2 gives Layer 5 no security services, so protect above or below it.

### Full forms
| Term | Meaning |
|---|---|
| PAP | Password Authentication Protocol |
| CHAP | Challenge-Handshake Authentication Protocol |
| EAP | Extensible Authentication Protocol |
| PEAP | Protected EAP |
| PPP | Point-to-Point Protocol |
| PPTP | Point-to-Point Tunneling Protocol |
| VPN | Virtual Private Network |
| RPC | Remote Procedure Call |

| PKI | Public Key Infrastructure |

### Pros
- Persistent, managed dialogues
- EAP-TLS and PEAP give strong authentication
- RPC enables distributed systems

### Cons
- PAP is easy to compromise
- Not explicit in TCP/IP
- Poorly kept RPC is risky

### Where it is used
Commercial: Wi-Fi enterprise logins (802.1X/EAP), VPN access, networked file and database calls. Defence: certificate-based remote access (PKI). Other: remote healthcare and remote administration.

### Threats and countermeasures
- **Threats:** Session hijack, MITM, ARP/DNS/hosts-file poisoning, SSH downgrade, MITB.
- **Defences:** Replace weak authentication, strong identity management, PKI, correct DNS, IDS/IPS/SIEM monitoring.

## 18. Layer 6: Presentation, translate, compress, encrypt

### Animation steps
1. **Serialise fields** (Sender L6 internal): Fields such as Name: J. Smith and Phone are turned into a standard form with names, contents and metadata.
2. **Compress** (Sender L6 internal): Data compression reduces size.
3. **Encrypt** (Sender L6 internal): Encryption protects the content.
4. **Presentation payload** (Sender L6 -> Receiver L6): Sent down the stack and across the network.
5. **Decrypt** (Receiver L6 internal): The receiver reverses the steps.
6. **Decompress** (Receiver L6 internal): Original size restored.
7. **Deserialise to app** (Receiver L6 internal): The application receives the data with its meaning intact.

### Working principle
1. Created so dissimilar hosts can share data.
2. Handles encoding, serialising fields, compression and encryption.
3. Sublayers: CASE (common services) and SASE (application-specific services).
4. No Layer 6 in TCP/IP; these functions sit in applications and libraries.

### Pros
- Hosts with different formats interoperate
- Compression saves bandwidth
- Encryption protects confidentiality

### Cons

### Where it is used

- **Defences:** Upgrade weak applications, deep inspection, WAF, ADP, zero trust, behavioural monitoring.

## 20. Layer 7: Application, services used by programs

### Animation steps
1. **DNS query** (Browser -> DNS): The browser (not itself at Layer 7) calls Layer 7 services through APIs. First it asks DNS for the bank’s address.
2. **IP address** (DNS -> Browser): DNS answers.
3. **TCP + TLS setup** (Browser -> Web server): Lower layers (4, 5, 6) set up a connection and secure it.
4. **HTTP GET /balance** (Browser -> Web server): The Layer 7 request is sent.
5. **Process request** (Web server internal): The server runs application logic and queries a database.
6. **HTTP 200 + page** (Web server -> Browser): The response returns and the browser shows it.

### Working principle
1. End-user apps (browsers, Teams, Excel) are not at Layer 7. They call its services through APIs.
2. HTTP/HTTPS carries web and e-commerce traffic and mobile code.
3. DNS, DHCP, LDAP, SNMP, SMTP and others support name, address, directory and management services.
4. Largest attack surface and most attacked layer.
5. HTTP/HTTPS move mobile code and executable content, a route for malware.

### Full forms

|---|---|

### Pros
- Rich services and applications
- Mobile code and flexibility
- Standard protocols make integration easy

### Cons
- Largest attack surface
- Complexity creates vulnerabilities
- Executable content brings malware

### Where it is used
Commercial: online banking, e-commerce, SaaS. Defence: command-and-control portals behind WAFs and MFA. Other: e-government, telehealth, education.

### Threats and countermeasures
- **Threats:** SQL/LDAP injection, rogue DHCP, DNS poisoning, SNMP abuse, HTTP floods, DDoS, XSS, drive-by malware.
- **Defences:** Block risky sites and bots, MFA, deep inspection, WAF/ADP, zero trust, user training.

## 21. Layer 7 attack: SQL injection and WAF defence

### Animation steps
1. **Malformed input** (Attacker -> Web app): Attackers target the largest attack surface.
2. **WAF inspects (defence)** (Web app internal): A web application firewall can spot the pattern and block it.
3. **Unsafe SQL** (Web app -> Database): Without defences, the input becomes part of a query.
4. **Data returned** (Database -> Web app): The database answers.
5. **Exfiltration** (Web app -> Attacker): Data leaves via normal services.

### Working principle
1. Also: LDAP injection, XSS, DDoS floods, parameter tampering.
